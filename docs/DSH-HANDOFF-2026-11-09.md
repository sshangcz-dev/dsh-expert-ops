## 5. DSH 原生聊天与页面联动

项目聊天复用宿主 `conversation.content` embedded 工厂和固定 chat 视图，包含宿主输入、附件、模型选择、消息流、执行与审批界面。未另建模型服务，client 无密钥。

接口来源已按本机宿主实现查证，具体见 `docs/native-project-chat.md`：

- `sessions.create({sessionId})`、`sessions.refresh()`、`manager.getListSnapshot()`。
- `sessions.retain(id,{source})` → `reference.ready` → binding；卸载释放 reference。
- `binding.session.rename(title)`；`SessionProvider` 显式绑定 reference。
- `binding.session.eventSource.getSnapshot()/subscribe()` 监听消息事件。
- `conversation.input.dock` 放入口，React Context 仅在本插件项目会话内提供，避免污染其他原生会话。

每个 project_id 对应独立 dsh_session_id。新建项目进入时创建绑定；已有项目首次使用时补建。先预留 UUID、合并并发创建、可用时使用 Web Locks；响应丢失后查宿主目录恢复同一 ID。已有绑定打不开时显示重试，不创建替代对话。

同项目首页与业务面板复用同一 AgentPanel/SessionProvider；切换项目时隔离消息与输入上下文。重命名/结束/软删除不改变会话 ID、不删除宿主历史。项目后续改名暂不自动改宿主会话标题。

自然语言联动目前是前端明确意图规则：只接收当前项目、首页状态下实时 append 的用户消息，忽略历史、assistant 消息、重复序号、问题和部分否定/歧义。识别“打开岗位要求”“生成 JD”“解析甲方需求”等进入岗位要求；“打开专家匹配”“按画像匹配专家”等进入专家匹配。新旧入口名称兼容。规则不是通用语义理解，复杂表达仍可能不覆盖。

**尚未实现业务工具驱动的成果写回。** 左侧/右侧示例业务数据不会因聊天接通而自动注入模型。未来应由业务工具返回 project_id、task_id、成果版本与目标视图等明确结果，再更新页面；不要从模型自然语言回复猜测保存成功。

会话隔离不等于文件系统隔离：项目会话沿用 DSH 工作目录与权限，不保证不同会话不能读取共享文件或记忆。
