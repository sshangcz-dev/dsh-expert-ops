# 专家画像：14 字段筛选设计

更新：2026-11-09。当前交付为卡片 UI 与本机条件数据结构；没有执行数据库查询、向量检索或自动淘汰候选人。

## 主线与规则

1. 结构化基础条件直接用于数据库匹配，只有填写值且 requirement=required 的条件构成硬筛选。多个必须条件按 AND 组合。
2. 明确不满足任一硬条件：排除。其余硬条件缺少专家资料：待核实。全部明确满足：进入语义匹配。用户已确认这一缺失策略。
3. requirement=preferred 只作为偏好排序，不排除人选；空值不产生查询谓词。条件缺失与专家资料缺失是两件不同的事。
4. 专业背景、从业经验、能力要求、特殊经历使用语义匹配，范围仅限硬筛通过的人选。待核实单独展示，不应被标为已满足硬条件。向量相似度不能覆盖硬条件失败。
5. 字段类型不等于强制程度：运营可将填写的基础字段设为“必须满足”或“优先考虑”。例如学校/单位可以仅设为偏好。语义文字不能直接转成隐式淘汰规则。

## 字段字典

全部 14 项允许 null。前端多值以顿号等分隔，保存为去重字符串数组；正式数据库应接入标准 ID/别名映射，不要将自由文字直接拼进 SQL。

| 分组 | 字段 | key | 值类型 | 运算/用途 |
|---|---|---|---|---|
| 专业与资质 | 所属领域 | domain | string[] / null | any_of 或 all_of |
| 专业与资质 | 资质证书 | certificates | string[] / null | any_of 或 all_of |
| 教育背景 | 最高学历 | education | enum / null | gte，最低学历 |
| 教育背景 | 最高学历学校 | school | string[] / null | any_of 或 all_of |
| 教育背景 | 最高学历专业 | major | string[] / null | any_of 或 all_of |
| 教育背景 | 毕业时间 | graduation | YYYY-MM / null | lte，指定月份及以前 |
| 任职与投入 | 工作单位 | employer | string[] / null | any_of 或 all_of |
| 任职与投入 | 职位 | position | string[] / null | any_of 或 all_of |
| 任职与投入 | 工作年限 | years | number / null | gte，单位年 |
| 任职与投入 | 工作时长 | hours | number / null | gte，单位小时/周，0–168 |
| 经历与能力 | 专业背景 | background | string / null | semantic |
| 经历与能力 | 从业经验 | experience | string / null | semantic，保留较大多行编辑区 |
| 经历与能力 | 能力要求 | abilities | string / null | semantic |
| 经历与能力 | 特殊经历 | special | string / null | semantic |

多值的“任一符合/全部符合”都需明确展示，尤其资质证书中的 CPA/ACCA 是任选还是同时要求不能由系统猜测。单值属性选多个值且要求全部符合可能无匹配，不能自动放宽。

最高学历当前枚举为高中/中专、大专、本科、硕士、博士。数据库实现前需核对专家档案的学历编码、同等学历规则和时间粒度；以存量数据字典为准。工作单位/职位是否以当前任职还是历史任职匹配也需在数据库接口中明确，本期不猜测这些接口。

现有 14 字段没有单列地域、语言、NDA、价格或档期。若这些在业务中成为必须条件，应后续增加对应结构化属性，或暂交人工核实，不能只因向量相似而认定满足。旧“其他条件”暂放历史补充区，不自动参与筛选。

## 前端交互

专家画像与岗位 JD 合为一张卡片，通过内部页签切换，每次展示一份成果。两侧编辑器保持挂载，切换不会丢失未保存修改；各自保留复制、保存与取消，支持方向键切换页签。基础字段按专业与资质、教育背景、任职与投入分组，两列紧凑展示；已填字段标记必须/优先。

点击值原位编辑；数值/年月/学历使用对应输入方式，其他固定字段支持多值。编辑状态可修改约束。保存/取消在画像卡片底部，复制仅复制已保存且非空的字段及规则。语义字段用多行文本，经历保留更大输入区。未保存草稿按项目保存在当前页面内存，刷新前提示。

## 持久化与迁移

- 新键：`dsh-expert-ops:profile-criteria:v2:<projectId>`。
- schemaVersion=2；missingPolicy=needs_verification；conditions 每项包含 value、operator、requirement。
- requirement 取 required / preferred / semantic；文本字段固定 semantic。
- 独立保留 `legacyOther`，不计入 14 条筛选条件，不进入复制的匹配条件。
- 旧四字段记录不删除：首次读取保留三个同名语义字段，其他基础字段留空；旧其他条件移至折叠历史区。不会从人工改过的自然语言中推断数字门槛。
- 无旧手工记录的字节示例仅根据既有原文初始化工作年限至少 2 年。未知字段仍为空。
- 保存验证失败/存储失败时保留草稿，不覆盖旧数据。修改画像不会自动重写 JD、改变当前候选人或运行匹配。
