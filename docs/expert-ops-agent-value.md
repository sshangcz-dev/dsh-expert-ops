# 从「人盯人」到「系统运营」
## 专家运营智能体的必要性、作用机制与价值主张

> 版本：v1.0 ｜ 面向：业务负责人 / 项目交付 / 专家运营团队
> 一句话：**我们缺的不是专家，而是把专家稳定转化为产能的系统。**

---

## 一页结论

1. **困境的本质是「状态不可见 + 动作靠人推」**。专家在不在、能不能干、干得怎么样，散落在企微、飞书、问卷、表格和个人的记忆里；每一个动作（催报名、约培训、催产能、传返修）都要由人发起一次。
2. **代价不是"忙"，而是三笔复利账**：流失账（重招重训的成本）、沟通账（每日逐级摸排的时间）、知识账（经验随人走、跨项目不复用）。
3. **智能体的必要性来自三个结构性缺口**：跨系统的状态感知、闭环的自动执行、经验的持续沉淀。这三点，加人、加表格、买 BI 都补不上。
4. **对留存率的作用不是"陪聊"，而是让专家被及时响应、被公平结算、被看见成长**——把不确定性从专家侧拿走。
5. **对数据产出的作用不是"催得更凶"，而是让产能可测、缺口可预警、质量可前置**——从催促转向调度。
6. **团队需要统一的不是工具，而是策略语言**：一套获取渠道分层、一套运营分层与生命周期、一套指标口径。

## 二、业务困境：供给不缺，缺的是转化系统

### 2.1 三个断点

```
供给（专家库/渠道/高校）
   │  ① 转化断点：招募、入项、培训全靠人推
   ▼
产能（可作业的专家）
   │  ② 反馈断点：质检、返修、结算滞后，问题发现太晚
   ▼
质量与规模（稳定交付）
   │  ③ 沉淀断点：经验留在个人身上，项目间不复用
   ▼
资产（可复用的数据与标准）
```

**断点一：转化断点。** 专家进来了，但从"报名"到"能干活"要经过审核、入项、入群、培训、考试、试标六道人工关卡。每一道都依赖某个人记得去推，任何一道卡住，供给就停在半路。ALE 项目已经出现信号：跨项目复用率低、专家流失率高、流失后重招重训成本高。

**断点二：反馈断点。** 产能和质量靠每日逐级摸排，链条从运营到组长到专家，时间差大；质检在交付末端才发现格式错、口径错，返修建议还要人工转述。**问题不是没发现，而是发现得太晚。**

**断点三：沉淀断点。** 专家档案、项目经验、标注规范、质检标准、结算规则、沟通口径，散落在个人经验、聊天记录、历史文档和表格里。换一个人接手，等于重新学一遍；换一个项目复用，等于重新搭一次。

### 2.2 现象清单（与现有流程梳理一致）

| 环节 | 现状 | 结果 |
|---|---|---|
| 专家招募 | 人工建表、多渠道分发、逐个登记 | 易遗漏、渠道效果说不清 |
| 信息入项 | 按甲方格式手动复制粘贴 | 慢、易错、格式反复打回 |
| 入群与准入 | 高校教师、保密企业无法入企微，需微信外部群 | 报名/审核/加入进度不可见 |
| 培训与试标 | 逐一约时间，回复慢 | 周期拉长，专家等待中流失 |
| 机审工具 | 缺按项目配置的检查项 | 格式问题留到人工质检 |
| 产能统计 | 逐级摸排，多方对时 | **当前最大痛点**：耗人且不准 |
| 数据汇总 | 企微 + 飞书双端，人工合表 | 口径不一致，复盘困难 |
| 质检返修 | 人工质检，建议人工传递 | 返修轮次多，专家体验差 |
| 消息通知 | 群通知容易被忽略 | 关键信息触达不到 |
| 专家维系 | 依赖资深运营的个人关系 | 人一走，关系断 |

### 2.3 根因：不是态度问题，是流程没有"状态机"

所有痛点的共同结构是：**对象（专家/任务/交付）没有唯一状态，动作没有触发条件，结果没有回写位置。**

- 专家现在处于"已报名 / 待审核 / 已入群 / 培训中 / 试标中 / 可作业 / 暂停 / 流失"的哪一态？答不上来。
- 该谁在什么时候做什么？靠人记。
- 做完之后状态变了吗？经常没变。

只要这三件事没有系统承载，"更努力"只会变成"更忙"。

## 三、困境的代价：三笔复利账

> 下列为测算框架，具体系数需用真实基线校准；先统一口径，再谈数字。

**① 流失账**

```
单次流失成本 ≈ 重新招募成本 + 培训与试标成本 + 爬坡期产能损失 + 项目延期风险
```

专家越资深，后两项越大。**留存率每提升 1 个百分点，省下的是复利，不是一次性费用。**

**② 沟通账**

```
每周沟通成本 ≈ 需触达专家数 × 人均触达次数 × 单次耗时 × 运营人数
```

按"每日逐级摸排"的方式，这部分成本随专家数**线性增长**，而人的时间不会增长。

**③ 知识账**

经验没有沉淀时，每一次人员流动都会让组织"归零一次"。这部分不进财务报表，但决定了**第 10 个项目能不能比第 1 个项目更快**。

## 四、为什么必须是智能体：三个结构性缺口

| 方案 | 持续感知状态 | 闭环执行动作 | 沉淀可复用经验 | 结论 |
|---|---|---|---|---|
| 再加运营人员 | ✗ 靠人记 | 部分 | ✗ 留在个人 | 线性增长，越加越贵 |
| 再加表格/看板 | 部分（要人填） | ✗ | 部分 | 只是把纸换成电子表格 |
| 外包客服/外包运营 | ✗ | 部分 | ✗ | 响应快但不懂业务，质量不可控 |
| **智能体 + 人** | **✓ 跨系统持续读** | **✓ 触发即执行** | **✓ 写回知识库** | **补的是结构性缺口** |

智能体的三个"非它不可"：

1. **跨系统**：企微、飞书、问卷、表格、平台数据库，人要在五个窗口之间搬运，智能体可以在一个上下文里读写。
2. **7×24 持续**：状态变化发生在夜里和周末，人的跟进发生在工作日 9 点——这段时间差就是流失发生的地方。
3. **可复制**：一个运营的 SOP 沉淀下来，第二个项目直接复用；人不行，人会累、会走、会忘。

**关键定位：智能体不是"替人做决定"，而是"把人从执行层抬到决策层"。** 它负责看得见、跑得动、记得住；人负责定标准、做判断、处理例外。

## 五、它具体解决什么：痛点 → 能力 → 指标

| 痛点 | 智能体能力 | 衡量指标 |
|---|---|---|
| 招募多渠道易遗漏 | 自动生成招募文案、按渠道发布、回收报名并去重 | 渠道覆盖率、报名回收率 |
| 入项资料反复打回 | 按甲方模板自动初筛与生成，缺字段先提示 | 一次通过率、入项周期 |
| 入群/准入不可见 | 检测报名→审核→入群进度，异常上报 | 入群完成率、平均等待时长 |
| 培训试标约不上 | 自动排期、持续督促、未响应升级到人 | 培训完成率、试标通过率、爬坡周期 |
| 格式问题留到质检 | 按项目配置机审规则，提交前自查 | 返修率、一次通过率 |
| 产能摸排耗人 | 每日自动收集产能、识别缺口、按人推送 | 产能数据完整率、缺口发现时效 |
| 企微飞书不互通 | 双端消息与数据自动同步、统一汇总 | 数据一致率、报表产出时效 |
| 群通知被忽略 | 关键事项一对一触达，未读升级 | 触达率、响应率 |
| 专家关系依赖个人 | 档案 + 历史 + 上下文建议，交接不断档 | 交接周期、复聘率 |
| 经验不沉淀 | 项目经验/规范/话术入库，检索即用 | 知识复用次数、新人上手周期 |

## 六、留存率：机制，而不是口号

### 6.1 专家为什么会走

专家（尤其是高校教师、行业资深人士）不是被"别家多给 50 块"挖走的，多数是被**不确定性**劝退的：

| 驱动因子 | 流失时的典型感受 | 智能体可做的事 |
|---|---|---|
| 响应确定性 | "问了三天没人回" | 报名/审核/培训/结算节点自动回执，超时升级 |
| 结算透明 | "干了多少、什么时候结，说不清" | 产能与结算口径可查，异常主动说明 |
| 成长可见 | "一直在做重复活，没长进" | 按能力匹配任务，记录成长轨迹与复聘优先 |
| 被尊重 | "群发通知、机器话术" | 固定通知用模板，其余由 AI 给人提供上下文，**由人来说** |
| 产能匹配 | "这活不适合我，硬着头皮做" | 画像与任务匹配，减少错配与返工 |

### 6.2 一条重要的边界

**专家是高质量人群，不能用机器话术去"运营"他们。** 正确分工是：

- 机器做**确定性的通知**（排期、材料清单、结算状态、异常提醒）——快、准、不漏；
- 人做**需要判断的沟通**（绩效反馈、复聘邀请、冲突处理）——由 AI 提供上下文与建议，人来说。

这条边界划错，留存率会反向下降。

### 6.3 留存指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 30/60/90 天留存 | 首次可作业后仍在岗的比例 | 看爬坡期是否健康 |
| 复聘率 | 结项后再次被选中的比例 | 看质量与关系 |
| 流失预警命中率 | 预警后 30 天内确实流失的比例 | 看预警是否有效 |
| 人均有效小时 | 有效作业时长 / 在册人数 | 看产能密度 |

## 七、数据产出：从「催」到「调度」

### 7.1 三个杠杆

**杠杆一：让产能可见。**
每日自动收集"谁在做什么、做到哪、卡在哪"，形成产能台账；缺口按项目排期反推，提前一周预警，而不是当天发现没人。

**杠杆二：让质量前置。**
机审规则按项目配置，提交前自查；返修建议结构化（哪一行、什么问题、怎么改），减少往返轮次。返修率下降带来的不只是效率，还有专家体验。

**杠杆三：让爬坡变短。**
培训材料、试标样例、常见错误库标准化，新专家按画像自动匹配对应培训包；考试与试标结果自动记录，形成"能否上岗"的客观依据。

### 7.2 数据产出指标

| 指标 | 定义 | 目标方向 |
|---|---|---|
| 人均日产能 | 有效标注量 / 在岗人数 / 天 | ↑ |
| 准时交付率 | 按计划完成的任务占比 | ↑ |
| 返修率 | 返修任务 / 总任务 | ↓ |
| 一次通过率 | 首次质检通过占比 | ↑ |
| 爬坡周期 | 入项到达到标准产能的天数 | ↓ |
| 产能数据完整率 | 有当日产能记录的专家占比 | → 100% |

### 7.3 飞轮

```
更多专家 → 更稳定的产能 → 更多项目 → 更多经验与标准
   ↑                                        │
   └──── 更好的匹配、更短的爬坡 ←───────────┘
```

飞轮转起来的前提是**每一步都留下数据**。这就是为什么"沉淀"不是附带收益，而是核心目标之一。

## 八、团队统一认识：专家获取与专家运营的核心策略

> 这一节是给团队对齐用的：策略只有一套语言，执行才不会各说各话。

### 8.1 专家获取：四个动作

| 动作 | 要解决的问题 | 关键做法 |
|---|---|---|
| **渠道分层** | 不同项目需要不同来源 | 自营库 / 供应商 / 基地 / 高校 / 内部推荐，分别记成本与转化率 |
| **画像标准化** | 需求一来，不知道要找谁 | 硬门槛（地域/语言/证书/档期）+ 加分项 + 排除项，内部版与对外版分开 |
| **入库即评分** | 专家库是"名单"还是"资产" | 入库时按维度打分（专业/经验/产能/报价/信誉），可检索、可排序 |
| **供给预测** | 临时抱佛脚 | 按项目 pipeline 反推未来 4 周缺口，提前启动招募 |

### 8.2 专家运营：分层 + 生命周期

**分层运营**（同一套动作不要用在所有专家身上）：

| 层级 | 特征 | 运营重点 |
|---|---|---|
| S 级 | 高产能、高质量、可带教 | 复聘优先、带新人、参与标准制定 |
| A 级 | 稳定达标 | 保产能、给成长路径 |
| B 级 | 达标但不稳定 | 找波动原因（档期/技能/沟通） |
| C 级 | 长期低产 | 培训或转岗，控制投入 |
| 预警 | 活跃度下降/负面反馈 | 48 小时内人工介入 |

**生命周期 SOP**：

```
招募 → 审核 → 入项 → 培训/试标 → 爬坡 → 成熟作业 → 复用/复聘 → 退出/归档
```

每一段都要有：**进入条件、负责人、标准动作、退出条件、数据回写点**。没有回写点的流程，等于没有流程。

### 8.3 度量体系：一个北极星 + 四个护栏

- **北极星：月度有效产能小时**（不是人数，不是任务数——是真正能交付的产能）。
- 护栏指标：**留存率**（人还在不在）、**准时交付率**（活干没干完）、**返修率**（干得好不好）、**单专家获取成本**（划不划算）。

四个护栏任何一个恶化，都不允许用北极星的增长来掩盖。

### 8.4 组织分工：谁做什么

| 层 | 人 | 智能体 |
|---|---|---|
| 决策层 | 定标准、定优先级、处理例外、对外承诺 | 提供数据、预警、方案建议 |
| 执行层 | 审核判断、复杂沟通、质量兜底 | 发布、催办、收集、同步、初筛、机审 |
| 沉淀层 | 确认规范、评审知识 | 归档、索引、检索、复用推荐 |

一句话：**人定规则，机器跑流程，例外回到人。**

## 九、90 天落地路径（对齐现有节奏）

| 阶段 | 时间 | 交付 | 验收标准 |
|---|---|---|---|
| 流程梳理 | 10/24–11/8 | 场景清单、指标口径、数据字段 | 业务确认痛点优先级 |
| Demo 与业务验收 | 11/9–11/15 | 需求→画像→匹配→审核工作台可演示 | 业务能跑通一条真实需求 |
| POC | 11/16–11/23 | 接真实产能与审核结果 | 一个项目完整跑通闭环 |
| 上线 | 11/24–11/30 | 接入企微/飞书、日常使用 | 运营每日使用率达标 |
| 评估与扩展 | 12/1–12/15 | 指标复盘、第二场景扩展 | 留存/产能指标有基线对比 |

**优先做的三件事**（对应 P0）：产能摸排与进度跟进、专家初筛与入项资料整理、培训试标与作业催办。这三件占了运营时间的大头，也最容易量化收益。

## 十、边界与风险

| 风险 | 表现 | 应对 |
|---|---|---|
| 专家体验 | 机器话术让专家反感 | 固定通知模板化，判断性沟通由人来做 |
| 数据合规 | 简历含个人信息，权限外泄 | 最小必要采集、分级授权、只索引摘要 |
| 幻觉与误执行 | 自动发出错误通知/错误结论 | 高风险动作人工闸门，可回滚，留痕 |
| 平台依赖 | 企微/飞书接口变更 | 适配层隔离，关键数据本地留底 |
| 组织变革 | 没人对指标负责 | 明确 owner，指标进周会 |
| 过度自动化 | 例外处理能力退化 | 保留人工通道，例外必须有人接 |

## 附录：指标定义速查

| 指标 | 口径 |
|---|---|
| 有效产能小时 | 通过质检的作业时长，剔除返修与无效时段 |
| 留存率（30/60/90） | 首次可作业后第 N 天仍在册且近 30 天有产出的比例 |
| 复聘率 | 结项专家在 90 天内被再次选中的比例 |
| 爬坡周期 | 从入项到连续 3 天达到标准产能的天数 |
| 一次通过率 | 首次质检通过的任务 / 提交任务 |
| 返修率 | 返修任务 / 提交任务 |
| 单专家获取成本 | （渠道费用 + 运营人力分摊）/ 新增可作业专家数 |
