# 项目 Agent 首页

点击项目名称或新建项目后进入首页。首页隐藏重复的「运营 Agent」标题栏。首页展示该项目的原生 DSH 对话，在原生输入框上方展示「需求与招募成果」「匹配看板」轻量入口按钮；按钮和侧栏子入口打开同一右侧业务面板。

## 会话与生命周期

首页、业务页复用同一个 AgentPanel 和 SessionProvider；切换功能不重新创建或 retain 会话。跨项目仍使用原有项目到 sessionId 映射。组件卸载释放 reference、事件订阅和会话状态订阅。

入口使用 DSH `conversation.input.dock` 列表插槽（官方 TodoDock 使用相同接口），通过本插件 React Context 约束，只在项目首页显示，不污染原生其他会话或业务页。原生 composer 保持底部。

## 自然语言导航边界

使用已核查的 `binding.session.eventSource.getSnapshot/subscribe`。仅处理实时 append 的 `user/message`、`source.kind=user`、递增 seq；读取 text 内容，不读取附件正文。忽略初始化/历史分页/重连 replace、assistant 内容和重复序号。

当前为明确任务的前端规则导航：生成 JD、解析甲方需求、编辑专家画像进入招募成果；按画像匹配专家、查看候选池、打开匹配看板进入匹配页。问题、否定和同时命中多个功能的请求保留首页。仅当消息属于当前项目且仍处首页时导航，避免抢走功能页和未保存编辑。请求被 DSH 接收后再导航；发送失败不会依乐观回显切页。

此导航不代表业务工具执行成功。真正解析、向量匹配和成果写回仍待后端接入。未来应由已注册业务工具的明确事件补充导航，不应从模型回复猜测执行结果。

## 验证

`node tests/project-home.cjs` 覆盖意图、否定/歧义、历史重放、重复序号、跨项目隔离、业务页保护、订阅清理。另运行现有 native-chat、artifact-edit、profile-criteria、candidate-board 测试及语法检查。

浏览器实测：原生会话发送「请打开匹配看板。仅演示导航，不要执行工具或修改文件，回复收到即可。」后进入匹配看板，聊天记录保留；首页入口位于原生输入框上方。业务解析与匹配尚未接入。

首页欢迎标题仅在原生会话 blank 且未发起消息时显示；乐观提交、运行中和已有历史均隐藏。输入区底色渐变回页面背景，入口行复用原生 composer 的 side-clearance 与 card-max-width，保持左边界一致。

## 右侧业务面板（2026-11-09）

布局为左侧项目导航、中间原生 Agent、最右侧业务面板。tab=home 时面板收起，对话恢复宽幅；recruitment/p3 时展开对应业务。使用同一套入口和原有自动导航，入口按钮持续显示并标识当前功能。项目标题在顶部，具体功能标题及关闭按钮放在面板内。

面板默认占工作区 58%，分隔线可拖动到 38%—70%；键盘左右键调节 2%，Home 或双击恢复 58%。动画 280ms，拖动时关闭动画，尊重 reduced-motion。Pointer Capture 结束/丢失时清理拖动状态，不注册全局鼠标事件。

面板收起使用 inert、aria-hidden 与 visibility，内部两个业务组件保持挂载（非当前功能 hidden），保留字段草稿、文件暂存、标签及筛选状态。更换项目通过组件 key 隔离。Agent 始终处于同一 React 位置，功能切换不更换 SessionProvider。

验证：首页入口与侧栏入口打开右侧面板；关闭后保持未发送聊天草稿，重新打开后 JD 标签仍选中；键盘调宽成功。现有 5 组逻辑测试通过。导出、分享、重新匹配仍为原有演示操作，未新增后端执行。
